## Context

The repository is a renamed fork at `aeei/docusaurus-theme`, with `origin/main` mirroring `PaloAltoNetworks/docusaurus-openapi-docs` and `shadcn-theme` carrying the product work. The current branch demonstrates the desired docs shell, but it edits the upstream OpenAPI theme and demo in place, mixes Base UI and Radix primitives, carries OpenAPI-only dependencies, and still exposes upstream branding/configuration in public surfaces.

The first public product is a general Docusaurus docs theme, not an OpenAPI renderer. It needs an installable package, a Markdown-first starter, a GitHub Pages demo, accurate attribution, and a branch shape that can be rebased onto future upstream changes with little textual conflict.

## Goals / Non-Goals

**Goals:**

- Ship `@aeei/docusaurus-theme` as a docs-only package using official shadcn Base Nova source and Base UI primitives.
- Let starter users work primarily in Markdown/MDX and static assets.
- Support GFM and official Docusaurus Mermaid rendering.
- Publish a representative starter to `https://aeei.github.io/docusaurus-theme/`.
- Make repository About, README, screenshots, starter navigation, and footer describe this project while retaining clear upstream provenance.
- Package all required license and third-party notice material.
- Restore upstream-owned package/plugin/demo paths so future upstream rebases are predominantly additive.

**Non-Goals:**

- OpenAPI rendering, API explorer, schema UI, or generated OpenAPI MDX in the core package.
- Math rendering, create CLI, custom domain, or an Algolia Admin/crawler implementation.
- Copying Nextra source or requiring Tailwind configuration in consumer sites.
- Publishing an OpenAPI addon in this change.

## Decisions

### 1. Add a new package instead of continuing the in-place fork

Create `packages/docusaurus-theme` and move only docs-relevant seams into it. Restore `packages/docusaurus-theme-openapi-docs`, `packages/docusaurus-plugin-openapi-docs`, `packages/create-docusaurus-openapi-docs`, and `demo` to `origin/main` after parity.

Alternative rejected: slimming the existing OpenAPI package. It keeps most conflicts and preserves unwanted runtime coupling. A fully separate repository was also rejected because this project intentionally retains GitHub fork provenance and sync behavior.

### 2. Use Docusaurus classic as the lower theme layer

The package overrides selected docs UI through Docusaurus theme aliases while classic retains routing, content loading, and fallback components. The package owns Layout/Navbar, docs sidebar, breadcrumbs, TOC, paginator, docs cards, code/Markdown presentation, color mode, mobile navigation, and back-to-top.

OpenAPI components and their dependencies do not cross the package interface.

### 3. Standardize interactive primitives on Base UI

Use official shadcn `base-nova` registry source first. The primitive inventory is:

- Button → `@base-ui/react/button`
- Badge composition → `@base-ui/react/merge-props` and `use-render`
- Sheet → `@base-ui/react/dialog`
- DropdownMenu → `@base-ui/react/menu`
- Tabs → `@base-ui/react/tabs`
- NavigationMenu → `@base-ui/react/navigation-menu`
- Tooltip → `@base-ui/react/tooltip`
- Separator → `@base-ui/react/separator`
- Sidebar/Breadcrumb composition → Base UI render utilities

Production imports and package manifests must contain no `radix-ui` or `@radix-ui/*`. Lucide is the only icon source. Contract tests own the inventory so a second primitive stack cannot re-enter silently.

### 4. Keep the consumer interface content-first

`examples/docs-starter` uses an autogenerated filesystem sidebar. Normal author edits are limited to `docs/**/*.md`, `docs/**/*.mdx`, and `static/**`. Front matter controls title/order. `src/css/tokens.css` and `docusaurus.config.ts` are explicit customization seams, not routine content files.

The starter is both documentation and an executable fixture for headings/TOC, links/images, GFM tables/task lists/strikethrough, code, admonitions, details, tabs, custom MDX, and Mermaid flowchart/sequence/state diagrams.

### 5. Use official Mermaid integration

Add `@docusaurus/theme-mermaid`, set `markdown.mermaid: true`, and validate diagrams in light and dark modes. No custom Mermaid renderer is introduced.

### 6. Treat the starter as the Pages source

Set:

- `url`: `https://aeei.github.io`
- `baseUrl`: `/docusaurus-theme/`
- `organizationName`: `aeei`
- `projectName`: `docusaurus-theme`

Pull requests run validation/build only. Pushes to `shadcn-theme` deploy `examples/docs-starter/build` with full-SHA-pinned official Pages actions and minimum `pages: write` / `id-token: write` permissions. After the first successful deployment, set the repository homepage to the Pages URL.

### 7. Make search optional and owner-correct

The first deployment omits Algolia config and search UI. It never copies the upstream app ID, search-only key, or index name.

After Pages is public, apply for Algolia DocSearch using the Pages and repository URLs. Search activates only when all of `ALGOLIA_APP_ID`, `ALGOLIA_SEARCH_API_KEY`, and `ALGOLIA_INDEX_NAME` exist. Only the browser-safe search-only key is accepted. Admin keys and personal tokens are unsupported. The existing token-driven DocSearch adapter remains available, and `Powered by Algolia` remains when enabled.

### 8. Replace public branding, not provenance

The root README is rewritten around `@aeei/docusaurus-theme`: live demo, real light/dark screenshots, quick start, authoring features, customization, development, roadmap, and attribution. Capture deterministic final starter screenshots at desktop `1440×900` and store WebP assets under `.github/assets`; a README `<picture>` selects light/dark by viewer preference.

The starter footer is concise:

- `Docusaurus Theme · Maintained by aeei`
- Docs, Markdown, GitHub, MIT, and Third-party notices links
- `Based on Docusaurus OpenAPI Docs by Palo Alto Networks`
- `Built with Docusaurus`

It does not list every dependency or claim a project-wide `© aeei` copyright. GitHub's automatic `forked from` relationship remains visible.

### 9. Centralize license/provenance data

Keep the upstream MIT notice. Add `THIRD_PARTY_NOTICES.md` and `LICENSES/`. Each notice records project, source URL, use scope, exact version/commit or registry snapshot date, copied file paths, SPDX/license identifier, and the package-local license-text path.

Record Palo Alto Networks, Docusaurus, shadcn/ui, Base UI, Lucide, Mermaid, and every actually shipped copied/vendored dependency. Nextra is identified only as a visual reference when acknowledged. Audit the current Toss-labelled typography values; replace them with a project-owned neutral scale if provenance/reuse terms are not explicit.

The npm tarball must include README, LICENSE, third-party notices, and applicable license texts. `npm pack` and clean-install tests verify this.

### 10. Keep rebase-only maintenance

The GitHub fork `main` is synced from its parent with `gh repo sync`. The product branch is rebased onto `origin/main` and pushed with `--force-with-lease`. Merge and squash merges remain disabled; rebase merge is enabled. `rerere` remains enabled locally.

The completion audit requires no diff under upstream-owned packages/plugin/demo paths.

### 11. Prepare a public scoped package

The package identity is `@aeei/docusaurus-theme`, initially versioned `0.1.0` while its public interface stabilizes. Build, `npm pack`, tarball audit, clean-install smoke tests, and `npm publish --access public` are mandatory. Publication is approved; execution remains blocked until this machine authenticates an npm owner of the `@aeei` scope.

## Risks / Trade-offs

- [Root README and lockfile can still conflict during upstream rebase] → Accept these as the only recurring hotspots and keep product code in additive paths.
- [Copied upstream components can drift semantically without textual conflicts] → Pin compatibility, retain contract/browser tests, and audit upstream theme changes per sync.
- [Restoring the old package before extraction is complete can lose behavior] → Preserve the current implementation until package/starter parity and tarball smoke tests pass.
- [Generic package name can obscure shadcn implementation] → State Base Nova prominently in description, README, keywords, and screenshots while keeping the product name stable.
- [Algolia approval may be delayed or rejected] → Pages launches without a dead search control; search is a later configuration activation.
- [Third-party provenance may be incomplete] → Treat license/provenance audit as a release gate; replace unclear assets/tokens instead of guessing.
- [Rebase rewrites public commit IDs] → Use rebase-only policy and `--force-with-lease`; collaborators rebase their feature branches onto the updated product branch.

## Migration Plan

1. Establish OpenSpec artifacts and contract tests for package boundaries, Base UI inventory, and attribution files.
2. Create `packages/docusaurus-theme` and migrate docs-only UI/styles without deleting the source reference.
3. Replace remaining Radix Button/Badge/Sheet/DropdownMenu implementations with official Base Nova equivalents.
4. Remove OpenAPI-only source and runtime dependencies from the new package.
5. Build `examples/docs-starter` with Markdown/MDX/Mermaid fixtures, semantic tokens, project navbar/footer, and no Algolia config.
6. Validate package build, starter build, browser matrix, and packed clean install.
7. Restore upstream-owned package/plugin/demo paths to `origin/main` and run the empty-diff audit.
8. Rewrite README, create final light/dark screenshots, and finish notices/licenses.
9. Deploy Pages and set the repository homepage.
10. After npm login confirms `@aeei` ownership, publish `0.1.0` publicly and verify registry metadata plus a clean registry install.
11. Apply for DocSearch after the public URL exists; enable only the resulting project-owned index.

Rollback before publication: reset to the last known-good current theme commit. Rollback after publication: deprecate the bad npm version, fix forward with a patch release, and redeploy the previous Pages artifact/commit.

None for implementation. npm authentication and Algolia DocSearch approval are explicit external gates handled at their respective tasks; `npm whoami` currently reports `ENEEDAUTH`.
